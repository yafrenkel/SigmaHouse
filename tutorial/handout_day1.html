Your training server is hello_iot.py. Start it, then open http://localhost:8081/. The server keeps every house in one Python dictionary called HOUSES.

Worked example — Collection vs Item

A resource is a thing you can point at with a URL. A verb (GET, POST…) is the action you do to it. You don't invent a new URL for every action — you point at the same resource and change the verb.

COLLECTION/api/houses the bucket of every house │ └── ITEM/api/houses/camp01 one house (keyed by its unique_id) │ └── ACTION.../toggle/led a switch inside that house

The collection — /api/houses

Verb + URLMeansThe server sends back
GET /api/housesread the whole list200 → [ {…}, {…} ]
POST /api/housesadd one to the list201 → {"ok": true, "unique_id": "camp01"}
# GET the collection — list everyone (empty until someone registers)
curl http://localhost:8081/api/houses
# → []

# POST to the collection — create a new house inside it
curl -X POST http://localhost:8081/api/houses -H "Content-Type: application/json" -d "{\"unique_id\":\"camp01\"}"

# → {"ok": true, "unique_id": "camp01"}

One item — /api/houses/camp01

Verb + URLMeansThe server sends back
GET /api/houses/camp01read that one house200 → the house, or 404 if it isn't there
POST /api/houses/camp01/toggle/ledflip its LED200 → {"ok": true, "led": true}
DELETE /api/houses/camp01remove that houseyour assignment 4 — not built yet!
# GET one item — just this house
curl http://localhost:8081/api/houses/camp01
# → {"unique_id":"camp01","ip_address":"127.0.0.1",
#    "state":{"led":{"active":false},"fan":{"active":false},"buzzer":{"active":false}}}

# POST an action on that item — toggle its LED
curl -X POST http://localhost:8081/api/houses/camp01/toggle/led
# → {"ok": true, "led": true}
The two "aha" moments:
  • Same URL, different verb: GET /api/houses reads the bucket · POST /api/houses adds to it.
  • Same verb, different URL: GET /api/houses gives you many · GET /api/houses/camp01 gives you one. The /camp01 is what narrows the collection to one item.

No terminal? Use the browser console (F12 → Console)

// register yourself (POST + JSON body)
fetch("/api/houses", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ unique_id: "camp01" })
}).then(r => r.json()).then(console.log)

// toggle its LED (POST — no headers or body needed)
fetch("/api/houses/camp01/toggle/led", { method: "POST" })
  .then(r => r.json())
  .then(console.log)

The short path /api/houses works because the page came from the hub, so it points right back at it — no CORS, no typing the IP.

Quick reference

curl flags

FlagDoes
-Xpick the verb (POST / PUT / DELETE). No -X = GET.
-Hadd a header — we use it to say "my body is JSON".
-dthe data / body you send.
-ialso print the status line at the top.

Status codes — the first digit is the mood

CodeMeans
200 OKit worked
201 Createdmade a new thing (you registered)
400 Bad Requestyou sent something wrong (bad/missing JSON)
404 Not Foundthat house doesn't exist

2xx = success · 4xx = your request is wrong · 5xx = the server has a bug. And remember: GET must be safe — it only reads. Anything that creates or changes (register, toggle) is a POST.
